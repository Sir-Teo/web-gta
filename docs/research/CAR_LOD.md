# Native car detail-distance gating

The ordinary car assembly now initializes high-detail mesh visibility and exposes `setViewDistance(distanceSquared, generationMultiplier)`. The scene caller must supply squared distance from the native clump root to its render camera and the generation-distance multiplier. Initial high detail is an adapter initialization policy, not a substitute for supplying camera state during gameplay.

The pinned [VisibilityPlugins.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/VisibilityPlugins.cpp) defines the body-detail threshold as `2 * (generationMultiplier * 70)^2` and the clump distance limit as `2 * (generationMultiplier * 150)^2`. High-detail callbacks require distance squared strictly below the first threshold; low-detail callbacks own equality and greater distances. Clump visibility includes equality at the outer limit. The wheel callback renders independently of the body-detail threshold. At multiplier one, the squared thresholds are 9,800 and 45,000, approximately 98.995 m and 212.132 m respectively.

The model renderer tags each mesh with its source atomic index. The car adapter binds those meshes in linear time and classifies low-detail atomics by the source frame's case-sensitive `_vlo` substring, following [SetAtomicRendererCB](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Models/VehicleModelInfo.cpp). Prepared wheel-frame identities select the wheel callback override. It changes mesh visibility only: hiding a chassis frame would incorrectly hide nested component and wheel frames as well. Disabled source atomics are never enabled by this binding.

Validation covers exact boundary ownership, multiplier scaling, invalid input without partial updates, nested frame preservation, wheel visibility through both body-detail ranges, assembly integration and disposal. The textured Greenwood browser diagnostic exercises both detail levels, complete distance culling and restoration without a manual `chassis_vlo` frame override. Unit and browser checks pass; this is not a retail pixel comparison.

The adapter does not implement native clump-sphere frustum culling, component dot-product culling, sorted alpha queues, clump alpha fading, multipass switching or the vehicle material pipelines. Standard Three mesh frustum behavior remains. Dynamic damage/component visibility will need composition with these gates. Published walking areas still do not install cars, so their scene scheduler does not yet provide vehicle camera-distance inputs.

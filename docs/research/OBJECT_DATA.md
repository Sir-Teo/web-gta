# Object definitions and placed entity classification

## Source contract

Pinned gta-reversed [FileLoader.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/FileLoader.cpp) loads `DATA/OBJECT.DAT` before the first IPL. `LoadObjectInstance` uses the selected model's object-info index: minus one selects `CBuilding` or `CAnimatedBuilding`; any assigned index selects `CDummyObject`. [BaseModelInfo.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Models/BaseModelInfo.cpp) initializes this index to minus one. Thus an IDE static-object section, immovable mass, fixed physics body or visible mesh is not sufficient evidence that an entity belongs to the native building category.

[ObjectData.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/ObjectData.cpp) reads a model name followed by seven floats and five integers as its minimum 13 fields. Optional fields are three effect-offset floats, an effect name, five breakable-property floats and two integers, for 24 total fields. Field order is encoded in `OBJECT_DATA_FIELDS`: model; mass, turn mass, air resistance, elasticity, percent submerged, uproot limit, collision-damage multiplier; damage effect, special collision response, camera avoidance, explosion flag, effect type; effect offset/name; smash multiplier, break velocity XYZ, velocity randomness, gun-break mode and sparks flag.

The loader ignores blank/semicolon lines, ends at an asterisk and uses common comma/control-whitespace normalization. The inspected source adds hash-comment skipping as a NOTSA change. It zeroes the property structure before scanning but does not initialize the temporary effect-name buffer. Consequently an enabled effect without its name is unsafe to interpret as a complete effect definition. The buoyancy calculation is `(100 / percentSubmerged) * (mass / 125)`; zero submerged percentage requires separate diagnostics.

Model lookup precedes assignment; unmatched names do not create models. Five default property records are initialized, some definitions reuse those defaults, and identical properties can reuse an earlier record. [ObjectData.h](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/ObjectData.h) reserves 160 records. This is not a 160-line file limit because model definitions can share property records. Mass 99999 can select an assigned default object record; it does not turn the model back into a building. Later dummy-to-object conversion and dynamic behavior are separate lifecycle work.

## Implemented raw reader

`assets/objectData.ts` preserves ordered rows, physical line numbers, raw numeric input units, field counts and absent optional values. It supports 13–24 contiguous fields, comments, a terminator, BOM and common delimiters. Required invalid tokens, integer-column lexical/range violations, nonfinite or float32-overflowing inputs and unsupported row lengths fail with line diagnostics. This deliberately stricter validation does not emulate malformed native `sscanf` partial scans or trailing garbage. Optional effect/buoyancy issues are retained with the row. No byte narrowing, default-property coalescing, effect lookup, buoyancy conversion or physics behavior is fabricated.

The browser's limits are 4 MiB of text and 50,000 raw model definitions, not the native property-record capacity. `indexObjectData` preserves last-definition lookup order with case-normalized model names while the raw ordered records remain available. `placedEntityKind` returns dummy for a defined model and building for an absent model only when a table is explicitly available. Without a table it returns unknown. It does not imply that unknown records are confirmed buildings.

## Required integration

Add explicit local object-data import before assigning native scene entity categories. Preserve the table's provenance and diagnostics, and keep unknown classification visible when the source is unavailable. Resolve definitions against the same model associations used for IPL assembly. Carry model/category ownership into each installed collider and remove that metadata when its placement is disposed. Update building-only sun LOS to filter verified dummy/object colliders while defining a visible policy for unknown sources. Do not disable physical collision merely because a model is a dummy. Follow up with native object-property conversion, capacity/deduplication rules and dummy-to-object behavior before introducing movable props.

Verification: 254 unit tests across 51 files and build passed. New cases cover all field positions, omitted/partial optional fields, line handling, termination, error diagnostics, duplicates and classification independent of mass. Synthetic definitions were used; no retail file was bundled or used to claim compatibility. The reader is not yet connected to local import or scene collision, so the playable fixed-collider obstruction approximation remains unchanged. Browser/production tests were not repeated for this unconnected data module.

## Session import and collider classification

Imported scenes now accept a local OBJECT.DAT through the Lighting panel's object-definitions disclosure. Parsing completes before classification changes; a malformed replacement retains the previous classification. Read-request tokens invalidate stale results after newer selections, reset or disposal. Files are neither uploaded nor persisted. The control is disabled in the authored scene, whose geometry has no native model association. Missing scene installation produces an explicit message rather than a false success.

Every installed collision source now owns an entity-kind field alongside its model/placement/surface metadata. Loading a table updates these records in place: listed models become dummy objects and absent models become buildings. Clearing restores unknown. Disposal clears the same source map, so no separate handle cache can outlive the colliders. Physics bodies and collider handles remain unchanged. The sun query applies a predicate that skips known dummies while retaining the fixed-collider fallback for unknown sources. This does not implement dummy-to-dynamic-object conversion, native mass/buoyancy/effects, original entity pooling or surface-specific LOS.

Verification: 256 unit tests across 51 files, all 50 browser tests, build and extended production smoke passed. Unit checks verify in-place metadata updates, preservation of collision, unknown reset, disposal and filtered sun rays. The imported-scene browser test loads definitions through the controls, verifies dummy classification, rejects a malformed replacement, clears back to unknown and resumes walking on the retained floor. Its menu capture was inspected. Production exercises the picker and clear flow without development hooks and reports `localObjectDataVerified`, no page errors and no external runtime requests. No retail file or original-game comparison was used.

## Car impacts on props, destruction and break pieces

Cars hitting OBJECT.DAT props now follow two fully reversed routines at the pinned revision: the static-object branch of `CPhysical::ApplyCollision` (Physical.cpp) and `CObject::ObjectDamage` (Object.cpp). `simulation/nativeObjectDamage.ts` ports both as pure functions over native units (mass, units per 1/50 s frame).

- **Impact.** The collision mass is `1 / (|r x n|^2 / turnMass + 1 / mass)`, and the intensity is `-(elasticity + 1) * mass * closing speed`, with the vehicle elasticity of 0.05 dropped after a wall hit. Bikes triple the object damage. ObjectDamage only runs above an object damage of 20 and only for props with a damage effect.
- **Damage.** Health starts at 1000 and loses damage times the collision-damage multiplier. The effect applies above 150 scaled damage or at zero health: change model, smash completely, change then smash, or breakable. Smashing turns off collision and visibility.
- **Response.** A destroyed prop gives the car only `n * intensity / (2 * multiplier)` in place of the collision response. `WorldCar` restores its pre-step motion and applies that impulse, one prop after another on the updated velocity. A surviving prop stays a wall when the intensity is within its uproot limit, when its limit is 9999 or more, or when its mass is 99998 or more.
- **Uprooting.** Above the uproot limit the prop unfreezes, and the same impact resolves through the general two-body branch of `ApplyCollision`: a common normal speed from both collision masses, the mean elasticity, a 0.3 cut to the car's vertical force below a normal Z of 0.7, the player car's 0.8 lever arm, and a 0.2 intensity push back for uproot limits above 200. The car gets its native impulse; the prop becomes a dynamic body with its OBJECT.DAT mass and turn mass, its centre of mass at its origin, its elasticity as restitution, air resistance as damping, and the native impulse as its starting velocity. Props with no damage effect are included, so parking meters move too.
- **Side effects.** Destruction plays `CAECollisionAudioEntity::ReportObjectDestruction`, a wood splinter or glass smash picked from the first collision sphere, box or triangle surface. `TryToExplode` sets off `EXPLOSION_OBJECT`, radius 10, half a unit up, once per prop with the causes-explosion flag, such as petrol pumps. The OBJECT.DAT effect plays on hit above 30 damage, on destruction, or both, unless the prop exploded.
- **Break pieces.** Breakable props hand their Rockstar breakable geometry plugin (rwID 0x0253F2FD, `assets/breakable.ts`) to a port of `BreakManager_c` and `BreakObject_c` (`simulation/nativeBreakObject.ts`, rendered by `render/BreakPieces.ts`). Pieces are grouped by material, or by face above the smash multiplier, prelit with the frame ambient, tumble for five frames, settle against the ground found below the object, puff smoke and optional sparks on landing, and fade over 256 to 287 frames. They step at the PC frame limiter's 30 fps (`APP_MAX_FPS`), because their lifetime counts frames.
- **Streaming.** A smashed prop stays removed, and an uprooted prop keeps its last pose, while its placement remains in the streaming window, including across window replacements. A prop that streams out is forgotten, as SA recreates the object when its area streams back in.

- **CJ on foot.** The player's movement sweep reports the props it runs into, and the ped branch of `ApplyCollision` decides the response. A static prop unfreezes when 70 times the closing speed, in units per frame, beats its uproot limit: any walk knocks bags and boxes loose, and only a sprint moves a traffic cone. A moving prop counts ten times its mass against a ped and takes the common-speed push, so CJ shoves loose boxes along.

Known differences:

- After uprooting, the prop's motion, its later contacts and its rest are Rapier's, not `CPhysical`'s. The speed-dependent air resistance used at 0.1 and below is replaced by no damping. `GetHasHitWall` is not tracked, so the elasticity term always applies.
- Change-model props do not swap to their damaged atomic; only their health and destroyed flag change.
- The fire hydrant water jet (`Fx_c::TriggerWaterHydrant` is still a retail stub), parking-meter money and glass window responses are not wired. Neither is the greenhouse's two-stage glass sound, the lamppost flag that flattens the normal, or the havoc and property-damage stats.
- Effects at a fixed offset use the rotated offset plus the object position. The reversed source adds the position a second time, which would place the effect at twice the object's coordinates, so it is treated as a transcription slip.
- Break pieces are drawn without fog and without the draw-last pass split. Pedestrians, other props and the player on foot do not damage props yet.

Verification: unit tests cover ObjectDamage thresholds and effects, the impact, response and two-body maths against retail OBJECT.DAT rows, the effect rule, the destruction sounds, the breakable plugin reader against the retail `lamppost3.dff`, and the break-piece simulation. Browser tests drive the Grove Street car north into a bag, a cardboard box and `lamppost3`, and separately into a fire hydrant. The car keeps going past the kerb, the lamppost throws three pieces that land and fade, and no smashed prop returns after the streaming window is replaced. The hydrant is uprooted, the car keeps more than 80 percent of its speed, and the hydrant stays dynamic and displaced after a window replacement. The start package `world-start.scene.bin` was rebuilt so its models carry the breakable plugin; apart from that field and its old warning, it matches the previous build. No retail capture was compared.

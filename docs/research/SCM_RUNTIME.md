# Original SCM execution core

Target: original PC 1.0. Research source: local gta-reversed checkout at `0076f9017b4aeef7433957ac2bd8b6988e9df166`, `Scripts/RunningScript.cpp`, `RunningScript.h` and `Commands/BasicCommands.cpp`.

`src/engine/ScmThread.ts` is the first executable script component. It is not yet connected to the gameplay loop and does not run the original campaign. It replaces neither the existing authored objectives nor the current initialization extractors until the necessary native command and lifecycle behavior is implemented and tested.

Implemented behavior:

- One-instruction decoding from a live instruction pointer; code following a jump need not be decoded as an uninterrupted instruction sequence. The existing whole-range parser remains available for data extraction.
- Shared mutable ScriptSpace globals (byte offsets), ordinary thread locals (32 values plus two timers), and caller-supplied local storage for future mission use. Values retain 32-bit integer/float bit representation. Arithmetic supports opcodes 0004–0017, including integer wrap, signed division and single-precision float stores.
- Greater-than, greater-or-equal and equality comparisons for the initial integer/float command families. Opcode negation and AND/OR accumulation follow `UpdateCompareFlag` (0x4859D0) and the ANDOR handler.
- Absolute global and negative base-relative branch targets per `UpdatePC` (0x464DA0), GOTO_IF_FALSE, an eight-entry GOSUB/RETURN stack, SCRIPT_NAME, NOP, WAIT and termination.
- WAIT records an unsigned millisecond deadline and yields even at zero duration. The caller must provide paused/game-scaled clock time and original scheduler ordering; this class does not invent a scheduler.

Unsupported commands stop with their opcode, name and byte offset, leaving the instruction pointer on the unsupported instruction. Unknown parameter kinds, invalid memory references and stack faults fail explicitly. A bounded instruction watchdog throws rather than silently advancing to another script; its limit is a browser diagnostic, not a claimed native behavior. Integer division by zero/overflow fails; no result is invented for native undefined/trapping arithmetic.

## Current original-script boundary

A direct execution probe against `public/play/world/files/scripts/main.scm` starts at its header entry 55976, sets the script name to `MAIN`, and stops at **DO_FADE (0x016A), byte 55987**. This is recorded as a regression. It proves original-bytecode dispatch and a truthful missing-command boundary, not execution of a mission or game initialization.

## Ordinary-thread scheduler

`ScmRuntime` now implements the ordinary active/idle script lists, 96-slot capacity, START_NEW_SCRIPT and termination. Sources: `CTheScripts::Init`, `StartNewScript`, `Process`, `CRunningScript::AddScriptToList` and `ReadParametersForNewlyStartedScript` in the same pinned checkout.

- Init prepends the 96 slots: slot 95 is allocated first. New threads are prepended to the active list. The loop saves its next pointer before running a thread, so a newly created thread first executes on the following processing pass.
- START_NEW_SCRIPT copies numeric arguments as raw 32-bit values, including float bits, from the parent's operands into the child's local slots. Later parent writes cannot change the copied arguments. Unsupported arrays/string arguments still stop explicitly.
- TIMERA/TIMERB are local slots 32/33. Before each thread processes, both receive the integer truncation of that frame's game timestep in milliseconds, even when the thread is asleep. Each addition wraps as int32. Mission-shared timers are not yet implemented.
- Termination removes the active thread and prepends its slot to the idle list. Reuse resets locals, timers, conditions, stack, wake time and the default `noname` name. Native external-script shutdown/resource cleanup remains missing.
- Pool exhaustion and malformed starts throw before publishing a new thread. The native exhausted-pool path is not emulated as an unsafe memory access.

`tests/scm-runtime.test.ts` checks execution order, deferred child execution, value-copy arguments, sleeping timers, per-frame truncation/overflow, the 96-slot limit, slot reset/reuse and invalid-start isolation. This scheduler is not yet invoked by the game loop; the original MAIN boundary remains DO_FADE at 55987.

## Expanded numeric execution and ordinary-script fade

Numeric global/local arrays now use `scm::ArrayAccess` and `ReadArrayInformation`: byte-offset global bases, slot-index local bases, signed index variables selected by the descriptor's high bit. The encoded count and element type do not constrain native numeric addressing; the browser checks the resulting address against real storage. START_NEW_SCRIPT inherits numeric-array argument support.

Variable arithmetic (0058–0077), timed float arithmetic (0078–0083), numeric copies/conversions (0084–0093), ABS (0094–0097), and constant integer assignments (04AE/04AF) follow `BasicCommands.cpp`. Timed arithmetic requires the native timestep, supplied by the scheduler as milliseconds / 20. Out-of-range float-to-int casts fail diagnostically instead of inventing a result for undefined C++ conversion behavior.

With a supplied world adapter, ordinary DO_FADE now calls the visual `ScmCameraFade` port of `CCamera::Fade/ProcessFade`. Direction 0 increases overlay alpha and direction 1 decreases it. Frame stepping, truncation, reversal from current alpha, the extra completion frame, and zero-duration asymmetry follow the pinned source. This is visual state only: music fading, mission-cleanup fade bookkeeping and renderer integration are outstanding. With no adapter DO_FADE still fails explicitly.

The packaged MAIN regression with this adapter reaches **SET_TOTAL_NUMBER_OF_MISSIONS (042C), byte 55993**. It does not yet initialize the world or run the campaign. The earlier DO_FADE boundary describes the adapter-free execution core.

## Text labels and shared random numbers

`ScmStrings` implements short/long global and local labels, short/long array element addressing, Windows-1252 literals, bounded copies with NUL padding, emptiness and case-sensitive equality. Pascal literals retain their explicit length for comparisons. Invalid addresses fail diagnostically; reads do not reproduce native out-of-bounds access for malformed unterminated labels. RETURN_TRUE/FALSE update the comparison accumulator, including opcode negation; they do not return from a subroutine.

GENERATE_RANDOM_INT and the integer/float range commands require an explicitly supplied shared random source. `ScmRuntime` passes the same source to every thread, including newly started scripts. No private seed or Math.random fallback is invented. The existing `WindowsCrtRandom` supplies the PC recurrence; range arithmetic follows the pinned `CGeneral` helpers and their float32 reciprocal/interpolation. Invalid ranges and samples fail diagnostically. Sharing and consumption order across the rest of the game engine is still outstanding.

Tests exercise original CRT samples in native active-list order, inclusive float/exclusive integer endpoints, string representation and padding, global/local array strides, cross-storage copies, predicates and bounds failures. The original MAIN boundary remains 55993, and gameplay integration remains open.

## Mission loading, native no-ops and game-state commands

Sources: `Scripts/TheScripts.h/.cpp` (ScriptSpace layout, `Init`, `Process`, `WipeLocalVariableMemoryForMissionScript`), `RunningScript.h/.cpp` (`GetLocal`, `Process`, `DoDeathArrestCheck`, `ResetIP`), `Commands/MissionCommands.cpp`, `Commands/ScriptCommands.cpp`, `Commands/UnusedCommands.cpp`, `Commands/ClockCommands.cpp`, `Commands/StatCommands.cpp`, `Commands/GameCommands.cpp`, `Commands/PlayerCommands.cpp`, plus `Clock.cpp`, `Stats.cpp`, `Wanted.cpp`, `Weather.cpp` and `Camera.cpp` in the same pinned checkout.

- `ScmRuntime.load` reproduces `CTheScripts::Init` storage: a 269,000-byte ScriptSpace whose first 200,000 bytes are MAIN.SCM and whose upper 69,000 bytes are the mission block. Mission offsets come from the header's MultiScriptArray; missions are read from the file on demand. The packaged file is 3,079,744 bytes, so only the lower block is resident, as on PC.
- LOAD_AND_LAUNCH_MISSION_INTERNAL (0417) follows `LoadAndLaunchMissionInternal`: exclusive-mission remapping from 0xFFFF, a read of up to 69,000 bytes over the previous block without clearing, wiped mission locals, a new thread whose base and instruction pointer are the mission block, `m_UsesMissionCleanup`/`m_ThisMustBeTheOnlyMissionRunning` set and `bAlreadyRunningAMissionScript` raised. The thread runs on the next pass, like any prepended script. `CTimer::Suspend/Resume` around the file read and `CGameLogic::ClearSkip` have no counterpart yet.
- Mission threads read and write `LocalVariablesForCurrentMission` (1,024 entries) through `GetLocal`; their own 34 local slots still receive the per-thread timer increments, and the mission-shared TIMERA/TIMERB advance once per `CTheScripts::Process` before any thread runs. Negative labels resolve against the mission base; positive labels still address MAIN.
- `CRunningScript::Process` ordering before the command loop: the death/arrest check for cleanup-owning threads, then the fail-mission reset. FAIL_CURRENT_MISSION sets the counter to 2; `Process` decrements it each frame, and a mission thread inside a GOSUB resets to its wrapper on the frame the counter reads 1. `ResetIP` in the pinned transcription post-decrements past the top of the stack and is annotated there as an original bug; the port unwinds to the outermost return address, which is the documented mission-wrapper behaviour, and fails explicitly on an empty stack.
- `DoDeathArrestCheck` requires the thread's death/arrest flag (SET_DEATHARREST_STATE), `IsPlayerOnAMission` (the DECLARE_MISSION_FLAG global equal to 1) and a restarting player supplied by the world adapter. It clears small HUD messages through the adapter, zeroes the flag, unwinds and marks the thread. Without an adapter no restart is in progress.
- LAUNCH_MISSION (00D7) starts an ordinary thread at the label; TERMINATE_ALL_SCRIPTS_WITH_THIS_NAME (0459) retires every case-insensitive match, including the caller. A retired script keeps its list pointers as native does, but the scheduler will not process it again in the same pass; native would walk into the idle list in that corner case, which is not reproduced.
- `ShutdownThisScript` (0x465AA0) is unreversed in the pinned checkout. Retiring a mission thread releases `bAlreadyRunningAMissionScript`; mission cleanup, streamed-script status and script-brain release are still missing.
- The 242 commands registered with `REGISTER_COMMAND_NOP` in `UnusedCommands.cpp` decode their operands and do nothing on PC 1.0: no stores, no condition update. The list is copied verbatim into `ScmNativeNops.ts` and every name resolves in the pinned opcode table.
- `ScmGameState` mirrors the statics scripts touch without HUD or rendering: `CStats` float/int storage (82 floats, 223 ints; stats 82–119 have no storage and fail explicitly), `SetStatValue`, `GetStatValue`, `SetNewRecordStat` and the capped-stat list; `CClock` initialise, `SetGameClock`, `NormaliseGameClock`, `Update` (without cheats or the days-passed stat), `GetGameClockMinutesUntil`, store/restore; `CWanted::SetMaximumWantedLevel` and its chaos table; `CWeather::ForceWeather`, `ForceWeatherNow`, `ReleaseWeather`; `CCamera::SetFadeColour`; `CHud::bScriptDontDisplayAreaName`; the frontend language.
- Handlers whose dispatch is still routed to the retail executable in the pinned checkout are marked "handler unreversed" in `ScmGameCommands.ts`: SET_TOTAL_NUMBER_OF_MISSIONS, SET_PROGRESS_TOTAL, SET_MISSION_RESPECT_TOTAL, DECLARE_MISSION_FLAG, SET_DEATHARREST_STATE, GET_GAME_TIMER, SET_FADING_COLOUR, the three weather commands, REQUEST_COLLISION, SET_RELATIONSHIP and SET_LA_RIOTS. Each sets one documented static or calls one reversed engine routine; none is a verified PC 1.0 handler transcription.
- World-touching commands go through optional `ScmWorldCommands` members (collision requests, scene loading, player creation and handles, camera reset, heading, relationships, riots, player control, playing/dead/restarting queries). A missing member stops the script at that command with the member name. CREATE_PLAYER stores the player index, as the reversed handler returns it.

## Messages, help text, intro text lines, switch tables and streaming requests

Sources: `Messages.cpp/.h`, `Hud.cpp` (`SetHelpMessage`, `SetHelpMessageWithNumber`), `Scripts/Commands/TextCommands.cpp`, `Scripts/Commands/ObjectCommands.cpp`, `Scripts/TheScripts.cpp` (`AddToSwitchJumpTable`, `UseSwitchJumpTable`, `ReinitialiseSwitchStatementData`), `Scripts/Commands/BasicCommands.cpp` and `Scripts/CommandParser/ReadArg.hpp` in the pinned checkout.

- `ScmMessages` ports the CMessages queues: eight brief slots, seven big-message styles of four slots, twenty previous briefs. Queued messages take the first free slot or are dropped; instant messages overwrite slot zero; only slot-zero or instant briefs enter the previous-brief list, which skips exact duplicates and shifts older entries down. `Process` drops an expired front message (inclusive boundary), promotes the next with a fresh timestamp and mirrors the front brief into the previous briefs. The pinned transcription shifts the array right at that point; the original closes the queue up, which is the behaviour reproduced. Messages hold GXT labels rather than resolved text: native pointer identity and `strcmp` coincide with label equality except for distinct labels with identical text. Number/string insertion, control-key substitution and drawing belong to the HUD and are not reproduced; no GXT file is in the content depot, so label resolution is an adapter concern.
- `ScmHelpMessage` follows `CHud::SetHelpMessage`: the three buffers are blanked before the permanent-message comparison, so CLEAR_HELP always blanks the text while leaving the state flag set for a permanent message. The blocking conditions (a queued STYLE_MIDDLE_SMALLER_HIGHER title, garage message, replay, cutscene) come from the message queue plus an adapter query.
- `ScmIntroText` holds the 96 `tScriptText` lines with their 0x4690A8 defaults; `CTheScripts::Process` resets them each frame while text commands are in use and disables them the frame after USE_TEXT_COMMANDS 0. DISPLAY_TEXT without an enabled state is an assertion in the source and fails here.
- Text handlers: PRINT, PRINT_NOW, PRINT_BIG, PRINT_BIG_Q, the numbered PRINT_WITH_n_NUMBERS(_NOW/_BIG) families, CLEAR_PRINTS, CLEAR_SMALL_PRINTS, CLEAR_THIS_PRINT, CLEAR_THIS_BIG_PRINT, CLEAR_THIS_PRINT_BIG_NOW, PRINT_HELP, PRINT_HELP_FOREVER, PRINT_HELP_FOREVER_WITH_NUMBER, CLEAR_HELP, FLASH_HUD_OBJECT, ADD_NEXT_MESSAGE_TO_PREVIOUS_BRIEFS, DISPLAY_NON_MINIGAME_HELP_MESSAGES, LOAD_MISSION_TEXT (adapter), USE_TEXT_COMMANDS, DISPLAY_TEXT(_WITH_NUMBER/_2_NUMBERS/_WITH_FLOAT) and the SET_TEXT_* attribute family. Subtitle-only "~z~" prints are dropped only when subtitles are off and the adapter resolves the label. The generated opcode table lists no operands for several unused numbered-print variants (0x2FC, 0x300, 0x305, 0x306, 0x309, 0x36E–0x371); those never occur in the packaged file and fail explicitly at operand access.
- SWITCH_START (0871) and SWITCH_CONTINUED (0872): the dispatch is unreversed, the table statics and helpers are reversed. START carries the value, case count, default flag and default address plus seven (value, label) pairs; CONTINUED carries nine more. The jump runs once every case has been read, through the reversed binary search over the sorted table, the two bracketing entries, then the default address; the table is reinitialised on each jump and before every thread runs. All 592 switches in the packaged file (178 continuation blocks, up to 67 cases) are sorted and carry a non-zero default address even in the 405 cases without an explicit default, which is why the default address is used unconditionally. An empty table would index with an unsigned wrap in the source and fails explicitly here.
- Constant-operand compares 04B0–04B7 follow the reversed `IsGreater`/`IsGreaterEqual` handlers in operand order; the 04A3/04A4 equality dispatch is unreversed and implemented as integer equality.
- REQUEST_MODEL, HAS_MODEL_LOADED, MARK_MODEL_AS_NO_LONGER_NEEDED and LOAD_ALL_MODELS_NOW route to the adapter; negative model operands resolve to the header's used-object names as `ReadArg` does through UsedObjectArray. `CScriptResourceManager` bookkeeping around those requests is unreversed and not modelled. GET_FADING_STATUS reads the adapter's `CCamera::GetFading` state.

## Radar blips

Source: `Radar.cpp/.h` in the pinned checkout (`SetCoordBlip`, `SetShortRangeCoordBlip`, `SetEntityBlip`, `GetNewUniqueBlipIndex`, `GetActualBlipArrayIndex`, `ChangeBlipColour/Brightness/Scale/Display`, `SetBlipSprite`, `SetBlipAlwaysDisplayInZoom`, `SetBlipFade`, `SetCoordBlipAppearance`, `SetBlipFriendly`, `SetBlipEntryExit`, `ClearBlip`, `ClearActualBlip`, `ClearBlipForEntity`, `FindTraceNotTrackingBlipIndex`).

- `ScmRadar` ports the 175-entry `ms_RadarTrace` table. Handles pack the slot index with a per-slot counter that wraps to 1 before 0xFFFF; stale handles resolve to -1 and every attribute change ignores them. `SetCoordBlip` discards its colour argument and always starts at BLIP_COLOUR_DESTINATION; `SetEntityBlip` colours chars and cars as threats and everything else green. Clearing keeps the counter, so a reused slot invalidates old handles. `ClearBlipForEntity` matches type and handle without a tracking check, which also clears every coordinate blip when called with (BLIP_COORD, 0). Drawing, alpha, legend and airstrip blips are not reproduced.
- Blip command dispatch is unreversed. ADD_BLIP_FOR_COORD/CHAR/CAR/OBJECT/PICKUP use BLIP_DISPLAY_BOTH and the sprite variants BLIP_DISPLAY_BLIPONLY plus `SetBlipSprite`; those display defaults are the conventional handler behaviour, not a verified transcription. REMOVE_BLIP, CHANGE_BLIP_COLOUR/SCALE/DISPLAY, SET_BLIP_AS_FRIENDLY, SET_BLIP_ALWAYS_DISPLAY_ON_ZOOMED_RADAR, SET_COORD_BLIP_APPEARANCE and DOES_BLIP_EXIST map one-to-one onto the reversed routines; SHOW_BLIPS_ON_ALL_LEVELS and HIDE_ALL_FRONTEND_BLIPS set the CTheScripts radar flags. SET_BLIP_ENTRY_EXIT needs the entry/exit pool and remains open. `tests/scm-radar.test.ts` covers handle encoding, counter wrap, table exhaustion, stale-handle immunity, appearance restrictions and the command surface.
- Sequence tasks (OPEN/CLOSE/PERFORM/CLEAR_SEQUENCE_TASK, about 5,500 sites) stay open: the pinned `CTaskSequences` only carries `Init`/`CleanUpForShutdown`, its slot allocator asserts, and the commands are unreversed.
- Pickups (CREATE_PICKUP, CREATE_PICKUP_WITH_AMMO, REMOVE_PICKUP, the property pickups mission INITIAL stops on; about 900 sites) stay open: `CPickups::GenerateNewOne` (0x456F20) still calls the retail executable in the pinned checkout, so slot selection and flag initialisation would be invented. Only the handle helpers (`GetActualPickupIndex`, `GetNewUniquePickupIndex`) are reversed.

### Coverage of the packaged MAIN.SCM

Counting every decoded instruction in the main segment and all 135 missions: 1,455 distinct commands, 360,439 instruction sites. The runtime now executes 265 distinct commands (145 core numeric/control/compare/switch/text/random, 20 native no-ops, 100 game-state, message, blip and world handlers) at 264,773 sites; 1,190 distinct commands at 95,666 sites remain unsupported. The most frequent open commands are entity and task commands: IS_CHAR_DEAD, IS_CAR_DEAD, CREATE_CHAR, SET_CHAR_DECISION_MAKER, the sequence-task family, mission audio, GIVE_WEAPON_TO_CHAR, SET_CHAR_COORDINATES, DELETE_CHAR, CREATE_CAR, camera positioning and ped tasks. Instruction-site coverage is not behavioural equivalence.

### Original MAIN boundary

With a recording world adapter, the original MAIN executes DO_FADE, mission/progress/respect totals, maximum wanted level 6, death/arrest state off, 08:00, REQUEST_COLLISION and LOAD_SCENE at Grove Street, four float and two integer stats, CREATE_PLAYER, DISPLAY_TIMER_BARS as a native no-op, 22 relationships, the player group and char handles, camera reset and heading 262, then LOAD_AND_LAUNCH_MISSION_INTERNAL 0 at 56361 and WAIT 0 at 56365. On the next pass mission INITIAL names itself, calls SET_LA_RIOTS 0, assigns its globals and stops at **CREATE_LOCKED_PROPERTY_PICKUP (0517), mission offset 868**. With only the visual fade adapter MAIN stops at REQUEST_COLLISION, offset 56022.

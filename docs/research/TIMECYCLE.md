# Native timecycle data

## Source contract

The pinned gta-reversed [TimeCycle.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/TimeCycle.cpp) reads weather-major rows with eight samples each. [TimeCycle.h](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/TimeCycle.h) names the eight samples; [eWeatherType.h](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Enums/eWeatherType.h) defines 23 slots, including underwater and two extra-color slots. A complete table therefore has 184 data rows. The sample hours are 0, 5, 6, 7, 12, 19, 20 and 22; 24 closes interpolation back to sample zero. The inspected calculation caps hours at 23.999 before selecting an interval.

The loader's scanning format contains 52 fields. Its warning condition is `n < 51`, so a missing final directional multiplier needs separate treatment. The code also documents a malformed retail row with shifted leading ambient fields. Do not silently repair a row or manufacture its missing final value and then label the result original data.

Field order is encoded in `TIMECYCLE_FIELDS`: static/object ambient RGB; unused directional RGB; sky top/bottom RGB; sun core/corona RGB; sizes and brightness; shadow strengths; far clip, fog start and ground light; cloud RGB; water RGBA; two post-effect colors stored alpha-first; cloud alpha; highlight minimum; water fog alpha; directional multiplier. The [file loader](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/FileLoader.cpp) replaces commas and control characters with spaces before scanning.

## Implemented reader

`src/assets/timecycle.ts` reads the raw numeric table and retains physical line numbers, weather index and sample hour. It accepts 51- and 52-field layouts, reporting the absent multiplier for 51-field rows. Other numeric field counts remain inspectable with an explicit unsafe-to-apply issue. Integer-column token mismatches are reported because native scanning would stop at such a token. Malformed numeric syntax, nonfinite numbers, incomplete/oversized tables and text above 1 MiB are rejected. No missing fields are filled from another row. Comments beginning with a slash, blank lines, a leading BOM, CRLF, commas and control whitespace are handled.

`timecycleInterval` supplies current/next sample indices and a blend fraction, including fractional minutes, overnight wrapping and the native upper-hour clamp. It does not interpolate or quantize color fields yet.

The reader deliberately preserves numeric precision. The source loader converts many values to bytes or int16, scales some sizes by ten, doubles post-effect alpha, and contains a suspicious nested byte conversion for the directional multiplier. [ColourSet.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Collision/ColourSet.cpp) then constructs/interpolates runtime color sets. These conversions and their rounding order must be checked before raw rows drive rendering; the current raw schema is not a display-ready color set.

## Prepared storage and base color-set sampling

`src/world/nativeTimecycle.ts` now prepares raw rows into named color-set fields. It applies byte/int16 narrowing, signed-byte size storage, float-input rounding, tenths scaling for sizes/ground light and doubled post-effect alpha before sampling. Raw rows are unchanged. Narrowing is explicitly modeled with truncation and modular integer storage; out-of-range float-cast behavior has not been validated against the original executable and must not be treated as a portable C++ guarantee. Synthetic edge tests document this model, including signed size and doubled-alpha wraparound.

The sampler first interpolates the two adjacent time samples separately for old and new weather, then interpolates those resulting sets by weather blend. Sky, sun, cloud and shadow integer fields truncate after each stage; ambient, water and post-effect fields retain float values. Float calculations use explicit float32 operations. A regression case distinguishes staged truncation (sky zero) from collapsing all four inputs into one blend (sky one), while ambient stays one. Midnight sampling wraps within the selected weather's eight rows.

Results remain in CColourSet storage units. Ambient division by 255, stored-tenths interpretation by downstream consumers and final display conversion are not silently folded into this sampler. The unused directional RGB columns are omitted from prepared output. Directional multiplier/illumination is also deliberately absent pending resolution of the source's nested cast; its raw input remains available in the original table. Missing or shifted required fields prevent preparation instead of yielding fabricated lighting.

All 227 unit tests and the build pass. New checks cover source-array preservation, storage/scaling boundaries, two-stage truncation, float-field interpolation, midnight wrapping and invalid controls. These are executable checks against the inspected transcription, not independent retail pixel or CPU-arithmetic verification. Altitude-dependent smog substitutions, boxes, tunnels, underwater/extra colors and other spatial adjustments are not applied. Local-file UI and renderer routing remain the next integration work; the playable lighting is still authored.

## Playable local-file integration

The game/pause menu now exposes a session-local timecycle picker, weather selector and authored-lighting reset. A replacement is parsed and prepared before becoming active; failure retains the current table. Read-request tokens prevent stale reads from overriding a newer selection, reset or disposed game. No table is uploaded or persisted. Weather labels follow the pinned enumeration.

`LocalTimecycle` caches the prepared sample for an unchanged clock and selection. Sky endpoints use an sRGB-to-linear conversion to fit the current Three renderer's sRGB output; this is an explicit presentation mapping, not verified original platform color processing. Static building ambient uses the sampled byte-scale values divided by 255. The scene receives that ambient before its hourly object-visibility cache, so changing a file/weather within the same minute applies immediately. Clearing restores the authored inputs. The existing fog color follows the horizon; fog distances/density, sky geometry/gradient, sun intensity/orbit, object/directional lighting, post-effects and spatial weather logic retain their previous policies.

Verification: 229 unit tests, all 47 browser checks, build and production smoke passed. Unit cases cover atomic replacement, caching, clear/weather controls, and building shader ambient within the same hour. The browser checks actual red/blue framebuffer pixels from an original synthetic table, weather switching, invalid replacement recovery, reset and resuming play. Production imports its own synthetic table through the real controls, verifies a red sky pixel, captures the panel and clears the override without a development hook. Production reported no page errors or external runtime requests. The menu screenshot was inspected. An ambiguous weather label was fixed to use an explicit association during browser validation.

This makes native table data usable in the playable renderer for the supported channels. It does not validate a retail file, repair known malformed retail rows, reproduce weather simulation or establish original-game pixel parity.

## Imported fog range and camera clip

The pinned [app.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/app/app.cpp) initializes fog color from sky-bottom RGB and selects linear fog, with fog initially disabled. [app_game.cpp](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/app/app_game.cpp) assigns the camera far clip and fog plane from the active timecycle. These establish application-level inputs, not every render pass's enable state. Microsoft's [fog formulas](https://learn.microsoft.com/en-us/windows/win32/direct3d9/fog-formulas) describe a linear visibility factor between the start and end distances.

The playable renderer now uses sampled fog start/end and sky-bottom color when start is nonnegative and end exceeds both start and the current game's 0.08 near-plane baseline. Invalid ranges retain authored exponential fog and report a diagnostic. Clearing the table restores the camera's captured original far clip. Projection updates precede native scene visibility selection. The sky projects onto the far plane and star positions scale inward for short clips, preserving the existing authored sky at imported distances.

`installNativeFogCurve` replaces Three's smoothstep fog factor with clamped linear camera-view depth in the shared shader library before game materials compile. This applies to ordinary fog-enabled materials and explicit building materials; exponential fog is unchanged. The current shader order blends fog after output color conversion. This is a chosen browser rendering policy, not a claim of original display-space or depth precision. The global chunk replacement is guarded by a GPU regression test against the installed Three version.

SkyGFX does not independently prove this policy: its pinned [shader build](https://github.com/aap/skygfx/blob/926616a3f31deaf0d300b3752383314db28994f0/shaders/shaders.bat) targets Shader Model 3, while the inspected simple pixel shader has no fog operation. The shader loader in `src/pipelinecommon.cpp` passes resource bytecode to RenderWare without a visible version rewrite. Microsoft's [Shader Model 3 documentation](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/shader-model-3) requires shaders to implement fog explicitly. Therefore application fog states alone cannot establish fog in that mod's building pass. Runtime bytecode, platform-specific pass behavior, spatial/altitude modifiers and matched retail captures remain unverified.

Verification: 230 unit tests across 45 files, all 48 browser tests, build and production smoke passed. The GPU probe checks seven depths before, within and beyond the range for both ordinary and building shaders, and verifies unchanged exponential fallback. Playable tests switch camera clips between 120 and 300, check actual sky pixels with the shortened clip, and restore 650. Unit tests retain sky data when fog ranges are invalid. Production exercised the real picker with a 120-unit clip, sky pixels and reset, with no page errors, external runtime requests or development hook. The production menu screenshot was inspected. An initial synchronous camera assertion was corrected to await the rendered frame before the successful targeted and full runs.

## Native altitude far-clip adjustment

The inspected pinned `TimeCycle.cpp` lines 493–501 reduce a far clip greater than 1000 above camera altitude 200: interpolate toward 1000 from altitude 200 to 500, then hold 1000 above 500. The imported lighting path now applies that adjustment to the sampled far clip, using camera world-space Y, and supplies the same endpoint to fog and camera projection. It does not mutate the source timecycle sample. Clearing native lighting restores the original camera far plane.

Numerical cases cover thresholds, intermediate altitude, negative altitude, short far clips and invalid inputs. A Chrome WorldLighting probe parents the camera under a group at altitude 350, verifies fog/camera 1600→1300, returns the parent to ground for 1600, then clears native lighting for the original 2000 camera range. Build and 483 unit tests/97 files pass. This is the altitude stage only; other spatial timecycle modifiers are still absent. The real Grove sample's 800-unit clip is unaffected. Source checks also confirmed that normal fog uses sky-bottom RGB (`source/app/app.cpp::DefinedState`) and that integer color interpolation was already present; neither was changed.

# Native vehicle color definitions

`readCarColors` imports the `col`, `car` and `car4` sections of the hash-verified public CARCOLS resource. `resolveCarColors` selects an explicit model variation and returns four resolved byte RGB colors for `bindNativeCarPaint`. Two-slot definitions set the third and fourth palette indices to zero. Later definitions replace earlier ones during normalized-name lookup; original rows remain inspectable.

The pinned [LoadVehicleColours implementation](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Models/VehicleModelInfo.cpp) reads at most eight combinations per vehicle and assigns zero to unused third/fourth indices in the two-slot section. The imported Stafford row has nine complete combinations. All nine remain raw metadata, with an issue; the resolver permits only the first eight. Random selection, mission overrides, respray rules and native model-name lookup internals are not reproduced by this explicit resolver.

The dataset contains 127 palette rows and 199 vehicle definitions (196 two-slot, three four-slot). Palette row 98 contains `77.93,96`. Its slot is retained with unresolved RGB, so subsequent indices never shift. The source has a `FIX_BUGS` branch for this typo. The importer neither enables that repair implicitly nor claims to reproduce malformed-input behavior of a particular original runtime. Selecting an unresolved or missing palette entry fails explicitly. Other malformed combinations also remain issues rather than invented colors. Structural corruption, resource limits and invalid model names reject.

The Greenwood has eight valid combinations. Its first uses indices `[30,26,0,0]`, resolving to `[66,31,33]`, `[165,169,167]`, black and black. The browser diagnostic now applies these colors to the textured native model, switches to the eighth listed combination to verify a framebuffer change, and restores the first for its screenshot. This replaces the earlier diagnostic paint scheme; it is not a random-spawn or mission-specific selection.

Validation covers two/four-slot data, duplicates, explicit variation bounds, independent returned colors, malformed palette index preservation, missing references, byte ranges, native combination limits, exact dataset counts and Greenwood associations. The existing browser check covers texture decoding, paint change, wheel rendering and GPU cleanup. Rendering still lacks complete vehicle lighting, reflections, distance callbacks and retail color-output verification. No vehicle is yet installed in the published walking areas.

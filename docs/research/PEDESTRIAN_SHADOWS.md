# Pedestrian shadow rendering

## Evidence and current gap

The native character already casts Three shadow maps, but imported building materials use baked lighting through MeshBasicMaterial. They do not receive Three's directional shadow pass. Simply enabling receiveShadow on those meshes cannot fix the missing ground shadow.

The pinned [CPed::PreRender](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Entity/Ped/Ped.cpp) selects a dummy textured shadow or a real-time shadow according to FX quality, player status and shadow availability. [CShadows](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/Shadows.cpp) reads `shad_ped`, calculates projection axes, supplies a four-unit depth range for pedestrian shadows and draws them separately on collision geometry. Real-time shadow registration uses a generated texture and SHADOW_INVCOLOR. Its light orientation uses the visible sun vector, independently of the fixed scene-illumination direction. Shadow strength depends on timecycle strength, camera distance, real-time intensity and receiving triangle day/night lighting.

The available `CastShadowEntityXY` and `CastShadowEntityXYZ` implementations are original-function trampolines. Their exact clipping, UV arithmetic and native floating-point behavior remain unestablished. The browser implementation below is an explicitly geometric replacement stage; it is not described as a complete reversed shadow pipeline.

## Implemented receiver geometry

`src/render/projectShadowReceiver.ts` accepts a COL triangle mesh, its world transformation and a horizontal projection footprint. The side half-axis maps to U and front half-axis to V. The footprint center supplies the upper height and a positive depth supplies the lower height. These are explicit API conventions; original raster orientation still needs calibration.

It transforms source triangles, rejects vertical/degenerate projected faces, reorients downward-wound faces, and clips each triangle against four footprint boundaries plus both height planes. Polygon triangulation preserves terrain slopes. UVs follow the original projection axes rather than stretching each clipped fragment. Output retains the original source face index and packed light byte per vertex, so receiver lighting can be evaluated independently of the character's foot-contact sample. Degenerate fragments are omitted. Invalid inputs and output-budget exhaustion throw before returning a partial result. Positions and UVs are converted to float32 for upload.

This stage is not yet called by the game renderer. It does not create a shadow texture, apply blend modes, add depth bias, select scene candidates, select shadow versus ordinary COL meshes, handle primitives/water, or reproduce native real-time shadow quality levels. No new visible shadow is claimed by this commit.

## Integration sequence

1. Use a spatial query over installed collision sources to select nearby receiver meshes; do not scan the entire imported scene each frame. Transform each selected source with its IPL placement matrix and clip into a shared bounded upload buffer.
2. Generate a skinned character silhouette render target using the source real-time shadow light orientation; verify its texture orientation and intensity against the original registration and render passes. Keep the dummy `shad_ped` path as a distinct native quality mode, once its raster is available.
3. Draw the projected shadow in a dedicated pass over the receiver geometry, applying per-triangle day/night attenuation and the appropriate blend mode. Verify depth bias, fog/order, overlapping receivers, stairs and airborne separation in real Grove Street captures.
4. Add resource ownership, scene replacement and context recovery checks before enabling the path by default.

## Inverse-color GPU draw pass

`ProjectedShadow` now owns a bounded, reusable receiver mesh and shader material. It borrows an intensity texture from its caller and combines projected receiver chunks into fixed-capacity dynamic buffers. Upload ranges cover only active vertices. Validation precedes mutation, so malformed input or overflow retains the previous valid draw. Clear releases the texture reference; disposal releases only owned geometry/material and is idempotent.

The pinned `CShadows::SetRenderModeForShadowType` selects source ZERO and destination INVSRCCOLOR for SHADOW_INVCOLOR. `AffectColourWithLighting` scales the supplied strength byte by the smaller of `0.4 + 0.6*(1-night)` and `0.3 + 0.7*lerp(dayNibble/30,nightNibble/30,night)`, truncating before texture modulation. The new pass performs that attenuation per source triangle and applies the inverse-color RGB blend. A black intensity texel leaves the destination unchanged; white applies full attenuated strength. Neutral and colored destinations retain their underlying color ratios.

`RenderStoredShadows` disables fog and depth writing, enables depth testing and disables face culling. The pass follows those states. Browser canvas alpha is explicitly preserved with separate alpha blend factors, because native backbuffer alpha is not browser-composited coverage. It expects a color-intensity raster; arbitrary texture-alpha cutoff behavior is not implemented. The texture owner must provide the intended clamp/linear sampling. Current polygon-offset magnitude and late transparent render order are browser integration choices requiring scene calibration.

Verification: 507 tests across 102 files with local references, build, and a GPU browser probe pass. Framebuffer checks cover day/night and zero-packed receiver lighting, partial strength, black mask, missing texture, explicit zero, footprint exclusion, colored terrain, foreground occlusion and retained framebuffer alpha. Unit checks cover capacity reuse, short upload ranges, atomic invalid updates, clearing and borrowed-texture ownership. An initial browser run caught a missing favicon in the probe page; the fixture now declares an inline icon and the final run has no console or page errors. Logs `/tmp/web-gta-shadow-pass-{unit,build,browser}.log`.

This pass is verified in a standalone GPU fixture and is not yet instantiated in GameRenderer. Animated silhouette texture generation, native real-time projection/blur/intensity lifecycle and game submission remain to implement. No visible character shadow in Grove Street is claimed by this stage.

## Animated silhouette raster

`CharacterSilhouette` now captures the current actor hierarchy into a 128×128, linear-filtered, clamped intensity render target without mipmaps or color-space conversion. The actor remains in its existing hierarchy and uses its existing GPU skeleton; capture does not advance animation. A temporary white unlit material replaces borrowed mesh materials for the pass and black clears the background. Siblings and unrelated world geometry are excluded. Frustum culling is disabled only during capture so cached skinned bounds cannot drop the moved silhouette.

The pinned [CRealTimeShadow](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/RealTimeShadow.cpp) creates its base camera with size exponent 7 and optionally resamples to exponent 6, then applies blur stages. [CShadowCamera](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/ShadowCamera.cpp) uses parallel projection, clears geometry lighting/texturing flags, renders atomics and inverts the raster. The browser capture produces the downstream white-mask/black-background representation directly; it does not reproduce that internal clear/draw/invert sequence or establish exact native mask values for every material type.

The camera is deliberately caller-supplied. Native radius/center/orientation and raster resampling/blur are still separate requirements. In particular, `SetLightProperties` ignores its second angle argument; reconstructing its orientation must follow the actual frame rotations rather than assuming a look-at vector from both angles. No game capture camera or automatic Grove shadow is added at this stage.

All temporary state restores in a finally block: original material references and culling flags, framebuffer and active face/mip, viewport/scissor, clear color/alpha, automatic clearing, XR setting, and both automatic and pending shadow-map updates. The class owns only its render target and temporary material. Disposal is idempotent and disposed captures fail before accessing caller objects.

## Native light-frame orientation

Resolved the frame composition against pinned primary sources. `CRealTimeShadow::SetLightProperties` replaces the frame with a Y-axis azimuth rotation and then post-concatenates an X-axis −90° rotation. Librw [base.cpp at 18532c2e13efbc1aa43f0b00b4459831f9414de0](https://github.com/aap/librw/blob/18532c2e13efbc1aa43f0b00b4459831f9414de0/src/base.cpp) implements post-concatenation as the new rotation applied after the existing transform. Its [camera.cpp](https://github.com/aap/librw/blob/18532c2e13efbc1aa43f0b00b4459831f9414de0/src/camera.cpp) identifies the frame's right vector as the camera's left, including the parallel-projection corners. Both pinned files were fetched and compared byte-for-byte with the initially inspected copies.

`nativeShadowOrientation` derives azimuth from the runtime visible-sun vector after accounting for native Z-up coordinates. The composed native frame has right `(cos(a),-sin(a),0)`, up `(0,0,-1)` and at `(sin(a),cos(a),0)`. Conversion to Three uses screen-right = negative converted native-right, screen-up = converted native-up and camera-back = negative converted native-at. The resulting capture points horizontally and has downward screen-up. The elevation argument is intentionally unused, matching the inspected function. This is the mathematical orientation; native float trigonometric roundoff is not claimed bit-identical.

The existing silhouette fixture now uses this orientation and native radius framing. An actor moving +X moves −32 raster pixels in the selected cardinal view, confirming the screen-left convention while retaining the 512-pixel mask area. Unit cases check cardinal directions, translated/rotated projection, elevation independence, the visible-sun samples and invalid azimuths. Verification: 518 tests/106 files with local references, build and silhouette GPU recovery test pass. One initial numerical test distinguished −0 from +0 in an otherwise identical vector; it now compares geometric distance. Logs `/tmp/web-gta-shadow-orientation-{unit,build,browser}.log`.

Capture orientation is now implemented. The raster-to-terrain mapping remains a distinct unresolved stage: the original real-time path calls `CastShadowEntityXYZ` with the real-time shadow object, and it must not be assumed to use the generic horizontal footprint UV convention implemented for the provisional receiver mesh. ## Resampling and paired bilinear blur

Implemented `ShadowRasterFilter` for the source's enabled-resampling path: a borrowed 128×128 intensity raster is copied into an owned 64×64 target, followed by a configurable number of paired bilinear blur copies. Two targets alternate without reading from the current destination. Each update starts with a fresh resample, so blur does not accumulate across animation frames. The class enforces square double-size, linear/clamped, non-color input and bounded pass counts, owns its targets/material/quad, and restores framebuffer, viewport/scissor, XR, clearing and shadow-update state.

The pinned `CShadowCamera::RasterResample` uses a destination-sized quad and +0.5/destinationSize UV offset. [Microsoft's D3D9 pixel-center explanation](https://learn.microsoft.com/en-us/windows/win32/direct3d9/directly-mapping-texels-to-pixels) places the first raster sample at screen coordinate zero, unlike WebGL's half-pixel location. Converting this quad to WebGL therefore requires no additional resample offset. Applying the native offset again would shift the result. `RasterBlur` alternates native UV offsets 1/size and 0; after pixel-center conversion these become +0.5/size and −0.5/size. The shader reverses the V offset to account for framebuffer texture coordinates increasing upward. This is the documented D3D9 interpretation, not an assertion of all original-platform raster conventions.

GPU verification independently calculates bilinear four-texel averages with byte rounding for zero, one and two paired blur iterations. Interior impulse placement and a corner impulse catch unintended shifts and clamp-order differences. The animated silhouette fixture now connects capture to this filter: 512 full-resolution mask pixels become 128 thresholded filtered pixels, and the −32-pixel pose shift becomes −16 at half resolution. Hidden actors produce empty filtered masks; state recovery still passes.

Final verification: 520 tests/107 files with local references, build and both filter/silhouette GPU tests pass. Initial TypeScript checking required an explicit shape for Three's broadly typed image metadata; the final build passes. Logs `/tmp/web-gta-shadow-filter-{unit,build,browser}.log`. Gradient darkening, quality-level selection, real-time intensity lifecycle, native sphere selection, terrain mapping and GameRenderer submission remain unfinished. These filters are connected in the GPU fixture, not yet in playable Grove Street.

## Intensity lifecycle and distance attenuation

The pinned [RealTimeShadowManager::Update](https://github.com/gta-reversed/gta-reversed/blob/0076f9017b4aeef7433957ac2bd8b6988e9df166/source/game_sa/RealTimeShadowManager.cpp) changes intensity by 3 per manager update: keep-alive raises it toward 100, otherwise it falls toward zero without unsigned underflow. Positive intensity updates/stores a shadow; zero can release its owner when initialized. Keep-alive flags reset after the manager loop. `stepNativeShadowIntensity` implements the numerical transition only; it does not yet allocate/release game owners or choose the manager update cadence. It deliberately accepts updates rather than seconds, so source frame dependence is not hidden behind a guessed fade duration.

`nativeShadowStrength` implements StoreRealTimeShadow's horizontal camera-distance stage: full strength through 7.5 units, linear fade to zero at 15, and no contribution beyond 15. Distance-attenuated strength is truncated before applying the 0–100 real-time intensity percentage and truncating again. For base strength 244, distance 10 and intensity 61, this yields byte 98; combining both fades before truncation would incorrectly yield 99. This output precedes per-receiver lighting attenuation and texture modulation.

LocalTimecycle now forwards the existing integer-interpolated shadow-strength channel. The inspected Grove sample at 17:25/weather 0 reports 138. No shadow draw is automatically enabled by loading it; lifecycle ownership and game submission still need integration.

## Final raster gradient

The filter now optionally applies the row gradient from `CShadowCamera::MakeGradientRaster` and the RGB multiplication from `DrawBlurryRaster2`. Native row zero starts at 128, then decreases by 64/height; for height 64, the last row is 65 rather than 64. The owned intensity texture preserves those discrete rows, in framebuffer orientation, with linear/clamped sampling. Gradient generation writes the row colors directly; the source disables vertex-alpha blending and clears its texture before drawing those rows. Exact native line-endpoint coverage is still not calibrated.

The multiplication pass samples the gradient using the source quad's zero UV offset, converted for WebGL pixel centers: (-0.5/size,+0.5/size). It multiplies the already-filtered raster into the spare target without feedback. The selected output target/texture follows whether the gradient was enabled. Each subsequent update begins with a fresh source resample, so toggling the gradient off does not retain prior darkening. The caller still selects this stage explicitly; gradient textures and targets are owned/disposed by the filter.
